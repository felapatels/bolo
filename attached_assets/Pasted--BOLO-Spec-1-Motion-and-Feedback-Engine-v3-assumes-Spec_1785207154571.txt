## 1. FEATURE SUMMARY

BOLO already has a mascot, confetti, idle animations, and partial haptics. The motion layer is in better shape than expected. This spec does four things:

1. **Adds the signature moment.** Session confetti becomes letterforms from the script being learned rather than generic shapes.
2. **Adds the XP arc**, using the counter and accessor that Spec 1a shipped.
3. **Adds what is missing**: wrong-answer physics, staggered stat count-up, an audio layer, and reduced-motion support.
4. **Fixes two behavioral bugs**: session confetti currently fires regardless of performance, and `nocatch` is treated as a learner error.

Nothing is created that already exists. No animation library is added.

## 4. COMPONENT CHANGES

### 4.1 Extend the existing Confetti components with a glyph mode

Add an optional prop to both `src/components/ui/confetti.tsx` and `components/Confetti.tsx`:

`glyphs?: string[]`

When provided, particles render as text glyphs instead of shapes, keeping all existing motion behavior. When absent or empty, behavior is unchanged.

Create one shared mapping module per app resolving a language code to a glyph set. Reuse the existing 12 script family grouping already present in the Script Trace feature. Do not define a new script mapping.

Use 8 to 12 representative letterforms per script, not the full inventory. Confetti is glanced at, not read.

### 4.2 Add an XP arc

Create per platform:
- `artifacts/gujarati-coach/src/components/XpArc.tsx`
- `artifacts/bolo-mobile/components/XpArc.tsx`

Animates a value from an origin position to the XP counter position obtained from the Spec 1a accessor, along a curved path, then triggers a pop on the counter.

### 4.3 Add an audio layer

Create per platform:
- `artifacts/gujarati-coach/src/lib/sound.ts`
- `artifacts/bolo-mobile/lib/sound.ts`

Exposes `playCue(name)` for `correct`, `wrong`, `session_complete`. Reads the preference from the Spec 1a `soundPref` module and no-ops when sound is off. Also no-ops silently when a cue file is missing, so the app works fully before any audio asset exists.

Mobile uses `expo-audio` if the installed SDK supports it, `expo-av` otherwise. Confirm before choosing and report which.

### 4.4 Add a reduced-motion helper

Create per platform:
- `artifacts/gujarati-coach/src/lib/motionPrefs.ts`
- `artifacts/bolo-mobile/lib/motionPrefs.ts`

Exposes `prefersReducedMotion()`, reading `prefers-reduced-motion` on web and `AccessibilityInfo.isReduceMotionEnabled()` on mobile.

## 5. BEHAVIOR AND LOGIC

### Script confetti

1. The system shall render session-completion confetti as letterforms from the script of the language just practiced.
2. The system shall resolve the glyph set from the existing Script Trace script family mapping, and shall not define a second mapping.
3. The system shall fall back to the existing shape confetti when a glyph set is unavailable, without error and without rendering empty boxes.
4. The system shall cap glyph confetti at 40 pieces on web and 25 on mobile, lower than the existing shape counts, because text rendering is more expensive than shape rendering.
5. The system shall leave per-phrase confetti on `band === 'nailed'` as shape confetti, unchanged. Only the session-end moment becomes glyphs.

### Fixing session confetti gating

6. The system shall stop firing session confetti unconditionally on `phase === 'done'`.
7. The system shall fire session confetti only when at least half the phrases in the session ended at band `nailed` or `close`.
8. The system shall show the session summary without confetti otherwise, with no negative animation. A weak session gets a quiet ending, not a punishment.

### XP arc

9. On a correct or `nailed` outcome, the system shall animate the awarded XP value from the result element to the XP counter position, then pop the counter.
10. The system shall obtain the target position from the Spec 1a accessor. If the accessor returns null, the system shall skip the arc silently and log a warning, since Spec 1a guarantees a mounted counter on every screen where XP can be earned. Do not build a fallback animation for this case.
11. The system shall complete the arc in 600 ms or less.

### Wrong answer

12. On band `retry`, the system shall shake the result container horizontally, three cycles at roughly 80 ms per cycle, amplitude no more than 8 px.
13. The system shall set the mascot to the existing `tryagain` pose, which is already the current behavior. Do not change it.
14. The system shall trigger a notification-warning haptic on mobile.

### Fixing nocatch

15. The system shall treat band `nocatch` as a system failure to hear, not a learner error.
16. The system shall show no shake, no negative haptic, no negative sound, and shall not set the `tryagain` pose for `nocatch`. Use the existing `thinking` pose.

### Session summary count-up

17. The system shall reveal each summary statistic in sequence on a spring, staggered by roughly 120 ms.
18. The system shall count numeric values up from zero rather than rendering the final value directly.
19. The system shall apply this at all three session summary sites: web practice, mobile practice, mobile review.

### Sound

20. The system shall play the `correct` cue on a `nailed` outcome, the `wrong` cue on `retry`, and the `session_complete` cue when the session summary appears.
21. The system shall play no cue for `nocatch`.
22. The system shall play no audio when the Spec 1a sound preference is off.
23. The system shall no-op silently when a cue file is absent.
24. The system shall respect the device silent switch on mobile and shall not play audio when backgrounded.

### Reduced motion

25. The system shall replace every animation in both apps with an instant state change when reduced motion is enabled, including the existing mascot idle animations and existing confetti, not only the animations added here.
26. The system shall continue playing sound and haptics when reduced motion is enabled.
27. The system shall never convey information through motion alone.

### Performance

28. The system shall animate only `transform` and `opacity` in everything added by this spec.
29. The system shall run all mobile animations added here through Reanimated worklets on the UI thread.
30. The system shall keep every animation added here at or under 900 ms.

## 6. ACCEPTANCE CHECKLIST

1. The system shall render session confetti as Devanagari letterforms for Hindi and Tamil letterforms for Tamil, and shall fall back to shapes without error for a language with no glyph set.
2. The system shall not fire session confetti for a session where fewer than half the phrases reached `nailed` or `close`.
3. The system shall animate awarded XP into the Spec 1a counter and pop it, on both platforms, with the accessor returning a non-null position in every case.
4. The system shall show no shake, no negative haptic, and no negative sound for band `nocatch`, on both platforms.
5. The system shall count session summary statistics up from zero with a visible stagger, at all three summary sites.
6. The system shall disable every animation in both apps, including pre-existing mascot idle and confetti animations, when reduced motion is enabled, while still firing sound and haptics.
7. The system shall play no audio when the Spec 1a sound preference is off, and shall run normally with zero audio files present.
8. The system shall install no new animation library, verified against both `package.json` files.
