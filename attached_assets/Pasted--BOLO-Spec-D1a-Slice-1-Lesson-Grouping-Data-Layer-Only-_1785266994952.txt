## 1. FEATURE SUMMARY

Add a `lessons` layer between categories and phrases: each category's phrases are partitioned into ordered lessons of ~10 phrases (8-12 acceptable at boundaries), preserving existing sort_order. Expose lessons via new read endpoints. Change nothing about how practice currently works.

The result: the data exists for the journey map and for future sequential gating, while the live app continues reading categories exactly as today.

## 3. DATA MODEL

### NEW table: `lessons`

| Column | Type | Notes |
|---|---|---|
| id | serial PK | |
| category_id | integer FK | |
| language_code | text | denormalized |
| position | integer | 1-based order within category |
| title | text nullable | null for now; naming is content work (fare-zone/station names come later) |
| created_at | timestamptz | |

Unique on (category_id, position). Index on (language_code, category_id, position).

### ALTER phrases

| Column | Type | Notes |
|---|---|---|
| lesson_id | integer FK nullable | null = not yet assigned; the grouping migration fills it |
| lesson_position | integer nullable | 1-based order within the lesson |

Nullable so the migration is separable from the DDL and re-runnable.

### Grouping migration (idempotent script, same pattern as backfillScoringV2)

For each (language, category): take phrases ordered by existing sort_order (report in Step 0 how stage interacts — do not interleave phrase-stage and sentence-stage within a lesson if they are currently grouped; keep stage grouping intact and partition within each stage block). Partition into lessons of 10; final partition of 4 or fewer merges into the previous lesson (so lessons are 8-14, target 10). Insert lessons rows, set phrase.lesson_id and lesson_position. Skip any (category) already fully assigned — idempotent, guarded like the scoring backfill.

Report the resulting distribution: lessons per category per language, min/median/max lesson size.

## 4. API (new endpoints only)

1. `GET /categories/:id/lessons` — ordered lessons for a category: id, position, title, phrase_count, and per-user progress summary (phrases attempted / phrases mastered within the lesson, derived from existing attempt/memory data — read-only derivation, no new counters).
2. `GET /lessons/:id/phrases` — ordered phrases within a lesson, same shape as the existing category-phrases response so a future client can swap scope without a new contract.
3. Both additive; schema source updated and clients regenerated; response fields optional per facts doc rules.

---

## 5. BEHAVIOR RULES

1. The system shall leave every existing endpoint's behavior and shape unchanged.
2. The system shall assign every phrase in every language to exactly one lesson, verified by a count: phrases with null lesson_id = 0 after migration.
3. The system shall preserve relative phrase order: within a lesson, lesson_position order equals prior sort_order order; concatenating lessons in position order reproduces the category's original sequence.
4. The system shall keep stage grouping intact per Step 0 findings.
5. The system shall make the grouping migration idempotent and safe to re-run.
6. The system shall derive lesson progress from existing data at read time; no stored counters.
