## 1. Problem Statement

Three defects observed in production chat, all traced to prompt content rather than code.

**Defect A, field confusion.** The chat call returns `reply` (Bolo's line in native script), `english` (translation of Bolo's reply), and `transcript_english` (translation of what the learner said). Intermittently the model fills `english` with a translation of the learner's utterance instead of its own reply, so the UI renders a gloss that does not match the native script above it. Observed evidence: in one failing case the learner's bubble and Bolo's gloss showed the same sentence with different punctuation, meaning two independent translations of the learner's line rather than one value duplicated. Confirmed intermittent, since a later session of three turns rendered all glosses correctly. This rules out a client-side field mapping error, which would fail deterministically.

**Defect B, verbatim echo.** Observed exchange: learner said "હું સારું છું." Bolo replied "હું સારું છું." The model repeated the learner's utterance word for word rather than responding to it. This is a conversational failure for a tutoring product.

**Defect C, Squawk script.** The persona's parrot noise renders as the Latin-script string "Squawk!" embedded inside otherwise native-script replies. Observed repeatedly in Gujarati output. It should appear in the target language's own script.

## 5. Behavior and Logic

### 5.1 Explicit field definitions

1. Add a clearly delimited section to `BOLO_PERSONA_PROMPT` defining each output field unambiguously. Each definition must state whose words the field contains.
2. Use wording to this effect, adjusted to match the existing prompt's voice:
   - `reply`: your own response, written in the target language's native script
   - `english`: the English translation of **your own reply above**, never a translation of the learner's words
   - `transcript_english`: the English translation of **what the learner just said**
3. Add an explicit negative instruction: the `english` field must never contain a translation of the learner's utterance. That is what `transcript_english` is for.
4. Add a self-check instruction directing the model to confirm, before returning, that `english` is a translation of `reply` and not of the learner's line.

### 5.2 No verbatim echo

5. Add an instruction prohibiting repeating the learner's utterance verbatim or near-verbatim as the reply.
6. Instruct the model that every reply must advance the conversation: answer what was asked, react to what was said, or ask a follow-up question.
7. Add a narrow exception: brief repetition is permitted only when explicitly correcting the learner's pronunciation or grammar, and in that case the reply must also include the correction or explanation. It must never be a bare repeat.

### 5.3 Squawk in native script

8. Instruct the model that the parrot noise must be written in the target language's own script, not in Latin script, unless the target language itself uses Latin script.
9. Do not hardcode a per-language transliteration table. The model has the script rules from `LANGUAGE_RULES_PROMPT` and can render the sound appropriately.
10. Do not change how often the parrot noise appears or where it sits in the reply.

### 5.4 Cache key version bump

11. Change `BOLO_CHAT_CACHE_KEY` from `bolo-chat-persona-v1` to `bolo-chat-persona-v2`.
12. This is mandatory. The persona constant is changing, so the old cached prefix must not be served.

### 5.5 Token budget

13. Report the token count of the combined system message after this change.
14. The combined message must remain above 1024 tokens so prompt caching still applies. It was previously well above that, so this should not be at risk, but confirm it.

## After The Build

Run at least six chat turns in one language, then check three things:

1. Every gloss under a Bolo reply matches the native script above it. Watch for a gloss that translates your own previous line.
2. Bolo never repeats your utterance back verbatim. Deliberately say something simple like "I am fine" in the target language, since that is the case that reproduced the echo.
3. The parrot noise appears in native script rather than as "Squawk!".

Then repeat in a second language with a different script family, ideally a right-to-left one such as Urdu, to confirm the script instruction generalizes.

Defect A is intermittent, so a single clean session does not prove it is fixed. If it recurs, capture the raw response payload showing the `reply`, `english`, and `transcript_english` values for the failing turn.
