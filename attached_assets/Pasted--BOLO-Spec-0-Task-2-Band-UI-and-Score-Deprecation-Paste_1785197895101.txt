## 1. FEATURE SUMMARY

Task 1 changed what pronunciation scoring means on the server. This task makes the clients reflect it, and begins deprecating the numeric score rather than removing it outright.

The numeric 0 to 100 score is replaced in the interface by a four-state band. The score field itself keeps being returned by the server in this release, because `bolo-mobile` is an Expo app with builds already installed on users' devices. Removing a field those builds expect would break the practice screen for anyone who has not updated. The field becomes optional now, stops being rendered now, and gets removed in a later task once adoption is measured.

This is a UI task plus a schema deprecation. No scoring logic changes.

## 3. SCHEMA AND CONTRACT CHANGES

### 3.1 Update the schema source, then regenerate

Locate the schema source that produces `PronunciationResult` and make these changes there. Then run the regeneration command and commit the regenerated output.

| Field | Change |
|---|---|
| band | ADD. Required. Enum `"nocatch" \| "nailed" \| "close" \| "retry"`. |
| xpAwarded | ADD. Required. Integer. |
| xpBreakdown | ADD. Optional. String. The human readable `multiplier_reason` already written to `xp_ledger`. |
| score | CHANGE from required to optional. Do not delete. |
| transcript, passed, feedback, tip, evaluationToken | Unchanged. |

### 3.2 Surface xpAwarded top-level in the response

`POST /openai/pronunciation` currently embeds `xpAwarded` in the signed token only. Add `xpAwarded` and `xpBreakdown` as top-level response fields on all three code paths (nocatch, fast-path, LLM).

The signed token remains the authority. The top-level fields are for display only. Do not decode the JWT on the client.

## 5. BEHAVIOR AND LOGIC

1. The system shall render the band label and never a numeric pronunciation score, in both apps, on every screen that displays a pronunciation result.
2. The system shall continue to return `score` in the API response in this release.
3. The system shall declare `score` optional in the generated types, so that a future release can stop sending it without a type-level breaking change.
4. The system shall return `band` and `xpAwarded` as top-level response fields on all three pronunciation code paths.
5. The system shall not decode the `evaluationToken` on the client for any purpose.
6. The system shall display the session XP total in the summary, sourced from the top-level `xpAwarded` values, not from summing scores.
7. The system shall show the empty state on a review screen when the due queue is empty, rather than an empty list or a spinner.
8. The system shall persist a timezone override to `users.timezone` and use it on the next streak computation.
9. The system shall render `feedback` and `tip` text unchanged from current behavior.
10. The system shall handle a response where `score` is absent without error, in both apps, since that is the state a later release will produce.
