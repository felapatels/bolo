# Spec D: TTS provider selection and audio cost instrumentation

Scope: API server only. Adds a cheaper TTS provider behind a configurable selector, and adds per-turn audio output logging so the cost difference can be measured.

---

1. No discovery phase. Only the files named in Section 3 may be modified.
2. Do not refactor, rename, or reorganize anything not named in this spec.
3. Anchors below describe code by name and behavior, not by line number. If what you find does not match the description, **stop and ask**. Do not reason around the mismatch and continue. Do not infer what the spec "probably meant". A mismatch is a hard stop.

## 2. Problem statement

**2.1 The most expensive available model is being used as a text-to-speech engine.** Reply text is already composed by a separate chat completion call. By the time synthesis runs there is no reasoning left to perform, yet synthesis runs on `gpt-audio` via `chat.completions.create` with `modalities: ["text", "audio"]`. Audio output on that model is billed at roughly five times the rate of a dedicated speech model. Measured usage shows audio output is approximately 85 to 90 percent of total spend.

**2.2 There is no way to select a different provider without editing function bodies.** `ttsConfig.ts` exports a single boolean, `USE_ELEVENLABS_TTS`. It expresses a two-way choice, so a third provider cannot be represented. The voice name is a hardcoded string literal inside `boloTTS`.

**2.3 Audio output volume is never measured.** The `onTimings` callback reports `ttsMs`, which is synthesis latency. Nothing anywhere records the byte count, buffer length, or duration of synthesized audio, and nothing records the character count of the text submitted for synthesis. Because audio billing scales with output length, this means the dominant cost driver is invisible in logs and the effect of any change to it cannot be verified.

## 4. Behavior and logic

### 4.1 New synthesis provider

1. Add a module-private async function `boloTTSMini` in `parrotChat.ts` with the signature `(text: string, languageName: string, languageCode: string) => Promise<Buffer>`, identical to the existing `synthesize` shape so it satisfies `ParrotChatDeps` without any interface change.
2. It calls the OpenAI speech endpoint (`audio.speech.create`), not `chat.completions.create`. Model `gpt-4o-mini-tts`, response format `mp3`.
3. It returns a raw MP3 Buffer. It must not return a wrapper object, a base64 string, or a stream. Callers receive naked binary bytes exactly as `boloTTS` and `boloTTSElevenLabs` do.
4. If the endpoint returns a web stream or array buffer rather than a Node Buffer, convert it to a Buffer before returning.
5. Errors thrown by this function must propagate unchanged so that `makeSynthesizeWithFallback` can classify them.

### 4.2 Voice configuration

1. Declare a module-level constant for the `gpt-audio` voice with the current value `shimmer`, and replace the hardcoded literal inside `boloTTS` with a reference to it. The value must not change.
2. Declare a separate module-level constant for the `gpt-4o-mini-tts` voice and use it in `boloTTSMini`. The two models have different voice sets and must not share a constant.
3. Do not add a voice parameter to any function signature. Signatures stay as they are.

### 4.3 Provider selection

1. Replace the single boolean export in `ttsConfig.ts` with a string-union provider selector supporting exactly three values: `gpt-audio`, `gpt-4o-mini-tts`, and `elevenlabs`.
2. The default value must be `gpt-audio`, preserving today's behavior exactly.
3. Retain `USE_ELEVENLABS_TTS` as a derived value computed from the selector, so nothing that reads it breaks. Do not search for other readers; if you find a reader outside the files in Section 3, stop and ask.
4. Wire `defaultParrotChatDeps.synthesize` from the selector:
   - `gpt-audio` selected: `synthesize` is `boloTTS` directly, with no fallback wrapper. `synthesizeStream` is omitted. This is the current behavior and must be byte-for-byte equivalent to it.
   - `gpt-4o-mini-tts` selected: `synthesize` is `makeSynthesizeWithFallback(boloTTSMini, boloTTS)`. `synthesizeStream` is omitted.
   - `elevenlabs` selected: unchanged from today's behavior when `USE_ELEVENLABS_TTS` is true, including the existing streaming wiring and the `boloTTS` fallback.
5. The selector is read once at module scope, as `USE_ELEVENLABS_TTS` is today. Do not read it per request.

### 4.4 Audio output instrumentation

1. Log one line per synthesis call, at info level, with the prefix `[tts]`.
2. The line must include: the provider selector value in effect, the model name actually called, the character count of the input text, the byte length of the returned Buffer, and the synthesis wall-clock duration in milliseconds.
3. The log must fire for all three providers, including the existing `gpt-audio` path, so that before and after measurements are directly comparable.
4. The log must fire on the path that actually produced the audio. If `makeSynthesizeWithFallback` routed to the fallback, the logged model name must be the fallback's model, not the primary's.
5. If synthesis throws, log one line with the same prefix recording the provider, the model attempted, the input character count, and the failure, then rethrow unchanged. Do not swallow the error and do not alter the existing fallback behavior.
6. Do not log the synthesized audio itself, any base64 payload, or the reply text content. Character counts only.

## 5. Acceptance checklist

1. The system shall provide a synthesis function targeting `gpt-4o-mini-tts` whose signature matches the existing `synthesize` dependency shape.
2. The system shall call the OpenAI speech endpoint rather than the chat completions endpoint for that provider.
3. The system shall return a raw MP3 Buffer from that function, with no wrapper object, base64 encoding, or stream.
4. The system shall propagate errors from that function unchanged so the existing fallback logic can classify them.
5. The system shall reference the `gpt-audio` voice through a named constant whose value remains `shimmer`.
6. The system shall use a separate named constant for the `gpt-4o-mini-tts` voice.
7. The system shall not add a voice parameter to any existing function signature.
8. The system shall expose a provider selector supporting exactly the values `gpt-audio`, `gpt-4o-mini-tts`, and `elevenlabs`.
9. The system shall default that selector to `gpt-audio`.
10. The system shall continue to export a working `USE_ELEVENLABS_TTS` value derived from the selector.
11. The system shall assign `boloTTS` directly as `synthesize`, with no fallback wrapper and no `synthesizeStream` key, when the selector is `gpt-audio`.
12. The system shall assign a fallback-wrapped pairing of the mini provider over `boloTTS` as `synthesize` when the selector is `gpt-4o-mini-tts`.
13. The system shall preserve the existing ElevenLabs wiring, including streaming and fallback, when the selector is `elevenlabs`.
14. The system shall read the selector once at module scope and not per request.
15. The system shall emit one info-level log line prefixed `[tts]` for every synthesis call.
16. The system shall include the provider, the model actually called, the input character count, the returned buffer byte length, and the synthesis duration in milliseconds in that line.
17. The system shall emit that line for all three providers including the existing `gpt-audio` path.
18. The system shall log the fallback's model name, not the primary's, when a call was served by the fallback.
19. The system shall log a failure line with the same prefix and rethrow unchanged when synthesis throws.
20. The system shall not log audio payloads, base64 data, or reply text content.
21. The system shall produce identical synthesis behavior to the current implementation when no configuration value is changed.
22. The system shall leave `makeSynthesizeWithFallback` internals, the ElevenLabs client, `runParrotTurn`, and all history handling unmodified.

## 6. Open questions

1. `gpt-4o-mini-tts` accepts an `instructions` parameter for prosody control. This spec does not use it. If pronunciation across Indic languages proves weak in comparison testing, that parameter is the first lever to try, but it is deliberately out of scope here so the swap can be measured cleanly first.
2. If the installed OpenAI SDK version does not expose `audio.speech.create`, stop and ask rather than hand-rolling an HTTP call or upgrading the dependency.
