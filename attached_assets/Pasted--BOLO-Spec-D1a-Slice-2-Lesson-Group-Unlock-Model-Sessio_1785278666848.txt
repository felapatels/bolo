## Feature summary

Sequential unlock of lesson groups within each (language, category), a test-out mechanism to skip ahead, insert-time group assignment for replenished phrases, and the two hardenings deferred from Slice 1.

## Data model

- lesson_group_progress table (or equivalent per existing progress-table conventions in the codebase, report in Step 0 if a convention exists): user id, lesson_group id, status (locked, unlocked, in_progress, completed, tested_out), timestamps. Additive only.
- Composite FK hardening from Slice 1 debt: enforce that a phrase's lesson_group agrees with the phrase's (language, category). Implement per the mechanism the review suggested; if the DB engine makes a true composite FK impractical, a CHECK-equivalent or trigger-based guard with a stated tradeoff is acceptable, state which and why.

## Behavior

1. Within each (language, category), the first lesson_group by position is unlocked by default; every other group is locked until the previous group is completed or tested out.
2. Group completion derives from the real mastery signal identified in Step 0 item 4. Do not invent a parallel completion notion.
3. Test-out: a user may attempt a short assessment for a locked group (composition and threshold to be proposed by you in the Step 0 report based on what the scoring system supports, with a recommendation, for my confirmation). Passing marks the group tested_out and unlocks the next group. Failing leaves state unchanged and is retryable.
4. Precedence: entitlement gating (gating.ts) always evaluates first. Unlock gating never grants access that entitlements deny. Where both would show a lock, the entitlement lock wins in any API response that must pick one reason. Confirm this composes with current gating.ts behavior in Step 0 item 1; stop if it does not.
5. Replenisher: newly replenished phrases are assigned at insert time to the last lesson_group of their (language, category) if that group is below the size cap from the Slice 1 partition rules; otherwise a new group is created at the next position. The idempotent regroup routine from Slice 1 remains the reconciliation backstop and must remain safe to run at any time.
6. Existing read-only endpoints from Slice 1 gain unlock status in their responses; response changes are additive fields only, no breaking shape changes.

## Verification

## Acceptance: the system shall

1. The system shall unlock the first lesson group of each language and category by default and lock all subsequent groups.
2. The system shall unlock a lesson group when the immediately preceding group in position order is completed or tested out.
3. The system shall derive group completion from the existing mastery signal and not from a new parallel measure.
4. The system shall provide a test-out assessment for locked groups that unlocks the group on a pass and preserves state on a fail.
5. The system shall evaluate entitlement gating before unlock gating and shall never grant access through unlock state that entitlements deny.
6. The system shall assign replenished phrases to a lesson group at insert time and shall create a new group when the last group is at capacity.
7. The system shall keep the regroup routine idempotent and safe to run at any time.
8. The system shall enforce agreement between a phrase's lesson group and the phrase's language and category at the data layer.
9. The system shall include unlock status in the Slice 1 read endpoints as additive response fields only.
10. The system shall leave bolo-mobile and all non-named surfaces unchanged.
