# Spec F: Streaming synthesis for gpt-4o-mini-tts

Scope: API server only. Populates `synthesizeStream` for the `gpt-4o-mini-tts` provider so audio playback begins on the first chunk instead of after the full clip is synthesized.

**Prerequisite: `TTS_PROVIDER` must be set to `gpt-4o-mini-tts` for this spec to have any effect. `gpt-audio` goes through chat completions and cannot stream audio. Do not attempt to add streaming to the `gpt-audio` path.**

## 2. Problem statement

Reply audio is fully buffered. The server waits for the entire clip to synthesize, then sends it as one base64 blob in the final `reply` event. Nothing plays until all of it arrives. Measured synthesis times range from 2.1 to 23.9 seconds for replies of similar length, and the learner waits through all of it in silence.

The client already supports the alternative and has since before this work began. It sends an `X-Audio-Stream: 1` header, it has MediaSource playback, and `startStreamPlayback` fires `setPhase("playing")` on the first chunk received. That entire path is dead because `synthesizeStream` is only populated when the provider is ElevenLabs.

`runParrotTurn`'s streaming branch is already provider-agnostic: it calls `deps.synthesizeStream` with a chunk callback and falls back to `deps.synthesize` if it throws. The `synthesizeStream` type signature contains nothing ElevenLabs-specific. Only the conditional spread that populates the key is coupled to the flag.

## 4. Behavior and logic

### 4.1 Streaming synthesis function

1. Add a module-private async function `boloTTSMiniStream` matching the `synthesizeStream` signature exactly.
2. It calls `audio.speech.create` with model `gpt-4o-mini-tts`, response format `mp3`, and `stream_format` set to `audio`. Use `audio`, not `sse`. The `audio` format yields raw audio bytes per chunk and requires no parsing.
3. Read the response body as a `ReadableStream` via `getReader()`. For each value received, convert to a Buffer and invoke `onChunk` with it.
4. Accumulate all chunks and resolve with the complete concatenated Buffer. Callers rely on both the progressive callback and the complete buffer as the resolved value.
5. Use the same voice constant `boloTTSMini` uses. Do not introduce a second voice constant.
6. Errors must propagate unchanged so `runParrotTurn`'s existing fallback to `deps.synthesize` can fire.

### 4.2 Wiring

1. Change the conditional spread so `synthesizeStream` is populated when the provider is `elevenlabs` (existing behavior, unchanged) **or** when the provider is `gpt-4o-mini-tts` (new, using `boloTTSMiniStream`).
2. When the provider is `gpt-audio`, `synthesizeStream` must remain absent. That path cannot stream.
3. Do not change which function is assigned to `synthesize` for any provider. Spec D set that and it stays.

### 4.3 Logging

1. Emit a `[tts]` line for the streaming path consistent with the Spec D format, including provider, model, input character count, total byte length of the concatenated buffer, and total duration.
2. Additionally include the time to first chunk in milliseconds. This is the number that determines perceived latency and it is not otherwise recoverable from the logs.
3. If streaming throws and the fallback runs, the existing Spec D logging on the fallback path reports the actual model used. Do not double-log a single successful synthesis.

## 5. Acceptance checklist

1. The system shall provide a streaming synthesis function matching the `synthesizeStream` dependency signature.
2. The system shall call the OpenAI speech endpoint with `gpt-4o-mini-tts` and `stream_format` set to `audio`.
3. The system shall invoke the chunk callback with a Buffer for each chunk received from the response stream.
4. The system shall resolve with the complete concatenated audio buffer.
5. The system shall use the same voice constant as the buffered mini provider.
6. The system shall propagate streaming errors unchanged so the existing fallback can fire.
7. The system shall populate `synthesizeStream` when the provider is `elevenlabs` or `gpt-4o-mini-tts`.
8. The system shall leave `synthesizeStream` absent when the provider is `gpt-audio`.
9. The system shall not change which function is assigned to `synthesize` for any provider.
10. The system shall emit a `[tts]` line for the streaming path including provider, model, character count, total bytes, and total duration.
11. The system shall include time to first chunk in that line.
12. The system shall not emit two `[tts]` lines for a single successful synthesis.
13. The system shall leave `runParrotTurn`, the ElevenLabs wiring, the circuit breaker, and all Spec E logic unmodified.

## 6. Open questions

1. The text input path in `sendTextTurn` does not send the `X-Audio-Stream` header, so text turns will remain buffered even after this lands. That is a client change and deliberately out of scope. Do not modify the client to address it.
2. If `stream_format` is not present on the SDK's speech params type in the installed version, stop and ask. Do not hand-roll an HTTP call and do not upgrade the dependency.
