## 1. FEATURE SUMMARY

Add a persistent XP display that shows progress toward today's goal, not a lifetime total.

A lifetime total is the wrong thing to animate into. It is a large number that barely moves, so an eight point gain is invisible and the feedback loop does nothing. Today's XP against `users.daily_goal` moves visibly on every answer, resets daily so it always feels achievable, and reinforces the daily habit that drives the streak.

The counter has two variants because it has to be on screen at the moment XP is earned, and the app chrome is inconsistent about that. On mobile, practice and review are full-screen with no tab bar. On web, practice has no `BottomNav` at phone width but does have `DesktopNav` at desktop width. A session variant that lives inside the practice and review screens themselves solves all four cases.

This spec also adds a sound on and off preference to the account screens. Nothing plays sound yet. The setting exists now because Spec 1 will add the audio layer that reads it, and both account screens are already being edited in this task.

## 3. API CHANGES

Add two fields to the `GET /progress/summary` response:

| Field | Notes |
|---|---|
| todayXp | Sum of `xp_ledger.xp` for the current calendar day in the user's IANA timezone, filtered by the same `userId` and `languageCode` as the existing lifetime sum. |
| dailyGoal | From `users.daily_goal`. |

Compute the local day boundary using the existing `localDayKey()` helper. Do not write a second date-bucketing implementation.

Update the schema source and regenerate. Do not hand-edit generated types.

The sound preference is client-local only. Do not add a column, an API field, or a schema change for it.

## 4. UI SPEC

### 4.1 XP counter component

Create one per platform:

- `artifacts/gujarati-coach/src/components/XpCounter.tsx`
- `artifacts/bolo-mobile/components/XpCounter.tsx`

Props: `{ variant: "chrome" | "session" }`.

Renders today's XP, the daily goal, and a progress indicator. Keep it small and quiet. This is chrome, not a feature. Derive all colors and spacing from the existing design tokens each app already uses. Do not introduce new tokens.

The `session` variant should be more compact than the `chrome` variant, since it sits inside an already dense header.

### 4.2 Placement

**Web chrome variant:** add to both `src/components/layout/bottom-nav.tsx` and `src/components/layout/desktop-nav.tsx`.

**Web session variant:** add to `src/pages/practice.tsx`. This is required at both breakpoints. At phone width there is no `BottomNav` on this page, and at desktop width the session variant takes precedence over `DesktopNav` per the accessor rule below.

**Mobile chrome variant:** add to the Home tab screen header. Do NOT add it to the tab bar. The Expo `Tabs` component renders tab items and is the wrong host for a counter.

**Mobile session variant:** add to the internal `PracticeHeader` in `app/(app)/practice/[id].tsx` at approximately line 1607, and to the equivalent header in `app/(app)/review.tsx`.

### 4.3 Position exposure

Each mounted instance registers its screen position with a module-level accessor, so a caller can ask for the active counter position without knowing which variant is on screen.

- Web: forward a ref, readable via `getBoundingClientRect()`.
- Mobile: forward a ref, readable via `measureInWindow()`.

When both variants are mounted, which happens on web desktop during practice, the session variant wins.

### 4.4 Reactivity

The counter updates immediately when XP is earned, without a full refetch. Optimistically increment from the `xpAwarded` value already returned in the pronunciation response, then reconcile against the server value on the next summary fetch.

### 4.5 Goal reached

When today's XP reaches or exceeds the daily goal, the indicator shows a completed state. No animation, no celebration. Spec 1 owns that moment.

### 4.6 Sound preference

Add a sound on and off toggle to both account screens, adjacent to the existing timezone row.

- Web: `src/pages/account.tsx`, Learning section, following the existing row pattern in that section.
- Mobile: `app/(app)/account/index.tsx`, following the existing `NavRow` pattern in that file.

Default on. Persist locally per platform, using whatever local persistence each app already uses. Do not introduce a new persistence library.

Create a small reader module per platform so Spec 1 can consume the value:

- `artifacts/gujarati-coach/src/lib/soundPref.ts`
- `artifacts/bolo-mobile/lib/soundPref.ts`

Each exposes a getter and a setter. Nothing else reads it in this release.

Label the toggle `Sound effects`.

## 5. BEHAVIOR AND LOGIC

1. The system shall display XP earned today in the user's local calendar day, not a lifetime total and not a UTC day.
2. The system shall compute the local day using the existing `localDayKey()` helper and shall not introduce a second date-bucketing implementation.
3. The system shall sum `xp_ledger.xp`, using the same `userId` and `languageCode` filters as the existing lifetime sum.
4. The system shall display progress against `users.daily_goal`.
5. The system shall render the chrome variant in both web nav components and in the mobile Home tab header.
6. The system shall render the session variant in the web practice page and in the mobile practice and review headers.
7. The system shall expose the screen position of the currently mounted counter through a single accessor, preferring the session variant when both are mounted.
8. The system shall increment optimistically from `xpAwarded` on the pronunciation response and reconcile on the next summary fetch.
9. The system shall reset to zero at local midnight without requiring an app restart.
10. The system shall handle a missing or null timezone by falling back to the timezone reported by the client, consistent with Spec 0 rule 37.
11. The system shall render a zero state without error for a user with no XP today.
12. The system shall persist a sound on and off preference locally, defaulting to on, and shall expose it through a reader module.
13. The system shall play no audio in this release. The preference is stored and read by nothing.

## 6. ACCEPTANCE CHECKLIST

1. The system shall show today's XP, not lifetime XP, on both apps.
2. The system shall show a different value for a user whose local date differs from UTC, verified with a test user in `Pacific/Auckland`.
3. The system shall increment visibly within one interaction of earning XP, without a manual refresh.
4. The system shall return a non-null position from the counter accessor during an active session on all four cases: web phone, web desktop, mobile practice, mobile review.
5. The system shall reset to zero at local midnight without an app restart.
6. The system shall render correctly at zero XP and at XP above the daily goal.
7. The system shall persist the sound preference across an app restart on both platforms.
8. The system shall play no audio anywhere, verified by confirming no audio API is called.

**Open note, not a build item:** `users.daily_goal` defaults to 10, and under the current XP economy a single nailed pronunciation attempt at neutral difficulty awards roughly 10 XP. The daily goal is therefore met in one attempt. That is worth recalibrating, but it is a product decision and not part of this task. Do not change the default. Report the observed median daily XP once there is data.
