SPEC: Zone test-out + cross-zone gate (dark) + attempt-time hardening. Chunk 4, commits A (server) and B (web).

Story 1: Zone test-out assessment

As a learner, I want to skip an entire zone by passing one assessment, so that prior knowledge moves me down the line without grinding stops I already know.

Business value: The designed escape valve for the linear journey; protects the gate's monetization path (token-priced retries later); web-first delivery exercises the flow before the store build.

Acceptance criteria:

The system shall provide a zone assessment sample composed of one plan-visible phrase per phrase-stage station of the zone, plus one per sentence-stage station whose content is plan-visible to the caller, capped at 10 phrases total with stations selected at random when the zone exceeds the cap.
The system shall serve a fresh random sample on each request with no sample persistence, and shall report sampleSize and requiredCorrect computed as ceil(0.8 x sampleSize) via the existing helper.
The system shall grade submissions only from server-signed evaluation tokens, rejecting any submission whose tokens are invalid, belong to another user, repeat a phrase, come from outside the zone's contributing stations, or include two phrases from the same station.
The system shall require exactly sampleSize verified attempts, recomputed from current zone composition at submission time, and shall pass the assessment when full-credit-band attempts meet requiredCorrect.
The system shall persist every valid submission, pass or fail, to an append-only zone assessment log.
The system shall throttle submissions to 3 per user per zone per rolling hour, checked before any token verification, responding 429 with Retry-After derived from the oldest in-window submission.
The system shall, on a pass, latch tested_out for every member group of the zone in one transaction, and shall award no XP and write no capstone stamp.
The system shall require the zone's content to be plan-visible before serving or grading an assessment: when any phrase-stage station has zero plan-visible phrases for the caller, the system shall respond with the existing upgrade-required denial and serve no degraded sample.
The system shall run all entitlement gates before any assessment logic, and shall never write progress rows for a language the caller's plan does not allow.

Story 2: Cross-zone progression gate, shipped dark

As the product owner, I want zones enforced in journey order behind a dormant switch, so that linearity becomes true at the serving layer the moment the mobile entry point exists, with zero user impact until then.

Business value: Closes the free bypass around zone test-out before its monetization lands; dark shipping decouples risk from the store review timeline.

Acceptance criteria:

The system shall, when CROSS_ZONE_GATE_ENABLED is true, unlock any group of a non-first category only when the preceding category in zone order has every group completed or tested_out; the first category shall always remain eligible.
The system shall treat a missing or non-true flag as off, with unlock derivation behaviorally identical to today.
The system shall apply the gate inside the shared unlock guard consumed by the journey listing and every phrase-serving route, so map and served content cannot disagree.
The system shall apply the gate check to both stop-level and zone-level test-out routes before their unlock exemptions, denying with a distinct non-retryable error that is logged distinctly from entitlement denials.
The system shall preserve unchanged: the retake exemption, ungrouped-phrase servability, teaser and showroom serving, and within-category sequencing.

Story 3: Attempt-time hardening

As the system owner, I want progression enforced at write time as well as serve time, so that the gate holds even if phrase text reaches a client by any path.

Acceptance criteria:

The system shall reject attempt writes for phrases in groups the caller has not unlocked, using the shared guard, except for ungrouped phrases and phrases with a prior attempt by the caller.
The system shall apply this check only on the plan-allowed path, leaving teaser and first-stop admission branches byte-identical.
The system shall deny with the existing lesson_group_locked error shape and a distinct log line, never a 402.

Story 4: Web entry and verdict (Commit B)

As a web learner, I want to start a zone assessment from the locked zone itself, so that skipping ahead is one tap from where I hit the wall.

Acceptance criteria:

The system shall offer zone test-out from the locked ZonePostcard and from the progression-lock dialog, launching the existing practice test-out mode scoped to the zone.
The system shall reuse the existing assessment flow unchanged: one take per phrase, no per-phrase persistence, verdict from the submit mutation, resubmit reusing collected tokens.
The system shall render the existing upgrade state, with copy unchanged, for plan-locked zones, derived upfront from the listing's access fields with the server 402 as backstop.
The system shall, on a pass, invalidate the category lesson-group listing and every member group's phrases so the returning map shows unlocked stops with Express stamps; on a fail, return to the journey by back-navigation with no in-place session reset.
