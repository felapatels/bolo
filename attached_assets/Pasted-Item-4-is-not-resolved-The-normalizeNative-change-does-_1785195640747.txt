Item 4 is not resolved. The normalizeNative change does not make हिंदी and हिन्दी match, and it typechecks clean because it is a logic bug, not a type bug.

Trace it: the final .replace(/[^\p{L}]/gu, "") strips all Devanagari marks, because matras, virama, and anusvara are all category M, not L. So हिंदी reduces to हद while हिन्दी reduces to हनद, because न is a letter and survives. They do not match.

Also note the explicit anusvara removal line is dead code. U+0902 is a nonspacing mark and would have been stripped by the non-letter rule on the next line regardless.

Fix: before the non-letter strip, collapse nasal consonant plus virama sequences. For Devanagari that means removing the sequence [\u0919\u091E\u0923\u0928\u092E] followed by \u094D, so that the conjunct nasal disappears the same way the anusvara does. Then both forms reduce identically.
