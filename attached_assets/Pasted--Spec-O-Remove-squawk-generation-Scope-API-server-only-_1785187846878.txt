# Spec O: Remove squawk generation

Scope: API server only. Stops the model producing parrot onomatopoeia in replies and subtitles, and removes the one canned greeting string that carries it.

---

## 1. Session rules

1. No discovery phase. Only the files named in Section 3 may be modified.
2. Anchors describe code by name and behavior. If what you find does not match, **stop and ask**. A mismatch is a hard stop. Do not infer intent, do not reason around the discrepancy, do not proceed on a best guess.
3. If satisfying this spec appears to require changing a file not listed in Section 3, **stop and ask**.
4. A failing test outside this spec's scope is a stop-and-ask, not a task to take on. You may fix a fixture that is invalidated by this change, but you may not change assertions, change test logic, or delete or skip tests.
5. One spec per session. Do not begin Spec P, C, G, H, I, or L.

---

## 2. Problem statement

Bolo's replies contain parrot exclamations that are spoken aloud by TTS. The learner hears "bawk" as speech rather than as a sound effect.

The prompt instructs the model to include an exclamation in roughly one reply in three, drawn from a fixed set, and to always write it in Latin script and never transliterate it into the target language. The model does not honour the script constraint. An observed Gujarati reply rendered it as બાવક, with the English gloss reading "How are you, Bawk?".

`extractSquawks` exists and strips these tokens from synthesis input, but it matches Latin-script tokens only. It cannot match a transliteration, and it cannot be extended to cover 22 scripts by adding tokens to a list. Since the exclamations are not wanted at all, the reliable fix is to stop generating them rather than to strip them after the fact.

## 3. Scope boundaries

### In scope

1. `artifacts/api-server/src/lib/parrotChat.ts`
2. `artifacts/api-server/src/lib/greetingStrings.ts`

### Named anchors

- `BOLO_PERSONA_PROMPT`, a module-level string constant, containing an instruction to occasionally include a parrot exclamation drawn from a fixed set, roughly one reply in three, always in Latin script and never transliterated.
- `buildSystemPrompt(languageName)`, a function containing the same exclamation instruction with the language name substituted, its own guardrail deflection strings, and a note directing the model to place parrot exclamations in the English subtitle field at the same position they appear in the reply.
- Three guardrail deflection strings in each builder that open with a parrot exclamation.
- `BOLO_CHAT_CACHE_KEY`, currently `bolo-chat-persona-v4`.
- `extractSquawks`, `findSquawkTokens`, and `normalizeSquawkConsistency`, plus the two squawk regexes they use.
- `buildGreetingDisplayText(languageName)` in `greetingStrings.ts`, an English fallback used when a language code is absent from `NATIVE_GREETING_MAP`, containing a literal squawk token.
- `buildGreetingTtsText(languageName)`, the parallel TTS string, which already has the token removed.
- `NATIVE_GREETING_MAP`, whose 22 entries contain no squawk tokens.

### Do not touch

1. Any client file, in either `artifacts/gujarati-coach` or `artifacts/bolo-mobile`. Client copy is Spec P.
2. The parrot identity itself. Bolo remains a parrot, the mascot is unchanged, and the 🦜 emoji stays wherever it appears. Only the written onomatopoeia is being removed.
3. `NATIVE_GREETING_MAP` entries. They are already clean.
4. `buildGreetingTtsText`. It is already correct.
5. The greeting cache key scheme and `GREETING_CACHE_KEY_VERSION`. That is Spec N.
6. Any TTS provider function, `ttsConfig.ts`, `ttsCache.ts`, the Spec D logging, the Spec E guard, or the Spec F streaming wiring.
7. The reply JSON schema, its property names, or its property order.
8. Transcription, history handling, abort handling, or the SSE route.

## 4. Behavior and logic

### 4.1 Remove the exclamation instruction

1. Remove the parrot exclamation instruction from `BOLO_PERSONA_PROMPT` entirely, including the list of permitted exclamations, the frequency guidance, the placement guidance, and the Latin-script constraint.
2. Remove the equivalent instruction from `buildSystemPrompt`.
3. Remove the note in `buildSystemPrompt` directing the model to mirror parrot exclamations into the English subtitle field.
4. Do not replace these with a negative instruction such as telling the model never to use bird noises. Removing the instruction is sufficient and a prohibition wastes prompt tokens on every turn.
5. Both builders must be edited. **Your original understanding may be that `buildSystemPrompt` is dead code. Do not skip it on that basis.** If you determine it is genuinely unreachable, edit it anyway and report its status separately.

### 4.2 Rewrite the deflection strings

1. Rewrite the three guardrail deflection strings in each builder so they carry no parrot exclamation.
2. Preserve their function, their friendly tone, and their instruction to redirect the learner back to the target language. Only the exclamation is removed.
3. Keep three options in each builder so the model retains variety.

### 4.3 Greeting fallback

1. Remove the squawk token from the English fallback string produced by `buildGreetingDisplayText`.
2. The display string and the TTS string must now match in wording except for the emoji, which stays in the display string only.
3. Change nothing else about greeting text.

### 4.4 Cache key

1. Bump `BOLO_CHAT_CACHE_KEY` from `bolo-chat-persona-v4` to `bolo-chat-persona-v5`, because the persona prompt text has changed.

### 4.5 Squawk stripping helpers

1. Leave `extractSquawks`, `findSquawkTokens`, `normalizeSquawkConsistency`, and both regexes in place and wired exactly as they are.
2. They become a safety net rather than a primary mechanism. They cost nothing and will catch a Latin-script slip if the model produces one unprompted.
3. Do not delete them. Dead code removal is Spec B's concern, and their status should be reassessed only after this change has been observed in production.

11. The system shall bump the persona cache key to `bolo-chat-persona-v5`.

## 6. Open questions

1. `buildSystemPrompt` was previously recorded as dead code and is now described as the live per-language path. Both cannot be true. Report which it actually is, since a pending spec plans to delete it.
2. Removing the exclamations makes Bolo's replies plainer. If the persona reads as flat afterwards, the remedy is warmth in the prompt's tone guidance, not reinstating onomatopoeia that TTS will speak aloud.
