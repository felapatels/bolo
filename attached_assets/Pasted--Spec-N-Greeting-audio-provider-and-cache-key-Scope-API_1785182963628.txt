# Spec N: Greeting audio provider and cache key

Scope: API server only. Brings greeting audio onto the configured provider, puts provider identity into the greeting cache key, and stops the greeting prewarm from being gated on ElevenLabs.

**Run after Spec M. The instructions digest this spec puts into the key comes from constants Spec M introduces.**

## 2. Problem statement

**2.1 Greeting audio plays in the wrong voice.** The greeting route synthesizes through the `gpt-audio` path, not through the provider resolver. After the provider switch, a learner hears an old-voice greeting followed by the configured voice for every subsequent turn, in the same session.

**2.2 The greeting cache key carries no provider identity.** `greetingAudioCacheKey` is a plain-string scheme with a version segment and no provider, model, voice, or instruction identity. Cached greetings synthesized under earlier settings continue to serve unchanged after any configuration change. This is the same defect Spec J fixed for phrases and Spec M extended to instructions, left in place here because both specs scoped the greeting path out.

**2.3 Greeting prewarm never runs.** `warmGreetings()` is gated on `USE_ELEVENLABS_TTS`. That flag is false for every non-ElevenLabs provider, so greetings are never prewarmed and every first session in every language pays cold synthesis. The flag is being used as a proxy for something it does not mean.

1. Any client file.

6. The greeting text strings themselves. This spec changes how greeting audio is produced and keyed, not what Bolo says.

## 4. Behavior and logic

### 4.1 Provider-aware greeting synthesis

1. On a cache miss, the greeting route must synthesize using the provider, model, voice, and instructions supplied by the resolver, not through a hardcoded `gpt-audio` path.
2. Use the chat instructions constant, not the phrase one. A greeting is Bolo speaking conversationally.
3. When the resolver indicates ElevenLabs, preserve today's ElevenLabs behavior for greetings.
4. Preserve the existing fire-and-forget cache write, the existing response shape, and the existing status codes.

### 4.2 Greeting cache key identity

1. Extend `greetingAudioCacheKey` to incorporate the provider, model, voice, and a digest of the instructions in effect, in addition to whatever it already includes.
2. Use a digest of the instruction text rather than the raw string so the key stays bounded.
3. Bump `GREETING_CACHE_KEY_VERSION` by one so entries written under the old scheme are never read back.
4. Do not delete orphaned rows and do not write a migration.
5. Both the route and `warmGreetings()` must compute the key through this one function with resolver-derived values. Neither may derive provider, voice, or instructions independently.

### 4.3 Prewarm gating

1. Remove the `USE_ELEVENLABS_TTS` gate on `warmGreetings()`. Greeting prewarm must run for whichever provider is configured.
2. `warmGreetings()` must synthesize through the resolver, matching 4.1.
3. Preserve the existing skip-if-already-cached behavior, computing the lookup with the updated key function.
4. Do not change the phrase character budget or the phrase synthesis loop.
5. If `warmGreetings()` currently contains ElevenLabs-specific logic that cannot run under another provider, **stop and ask** rather than restructuring it unilaterally.

### 4.4 Logging

1. Log one info-level line per greeting request prefixed `[greeting-tts]` recording provider, model, voice, language, hit or miss, and elapsed milliseconds.
2. Log a `[greeting-tts]` summary at prewarm completion recording provider, how many greetings were already cached, how many were synthesized, and how many failed.
3. Do not log audio content, base64 payloads, or full instruction text.

## 5. Acceptance checklist

1. The system shall synthesize greeting audio on a cache miss using the provider, model, voice, and instructions from the resolver.

## 6. Open questions

1. This orphans every cached greeting. That is intended, and it is cheap: greetings are one short clip per language, and the prewarm will refill them now that it actually runs.
2. If the greeting prewarm has no concurrency or pacing controls of its own and previously relied on ElevenLabs-specific throttling, stop and ask before removing the gate, so ungating does not produce a burst of synthesis calls at startup.
