# Tear-off pieces must carry their own card stock

**Rule (final, user-approved after 3 rounds):** tear the card into pieces that ALL move, and let the gap show the real page. Concretely: (1) BOTH halves animate away from each other (one side only reads as content sliding off an intact card); (2) each half carries its own copy of the card background, rounded outer corners, a jagged STATIC clip-path rip edge, and a STATIC `filter: drop-shadow(...)` (box-shadow does not work: clip-path clips it away); (3) the card container itself goes transparent for the tear (bg, shadow, glow, deco layers, overflow-hidden all off) so the widening gap shows whatever is actually behind the card. Do NOT paint the gap with a color: a page-colored underlay reads as a white box behind the card, a darkened recess reads as a container too; transparency is what reads as "floating over the page". Add a grip-then-give wobble (brief counter-rotation) and slight sag. Animate transforms/opacity only; clip-path and filters stay static. Make it slower than feels right in isolation: the user asked twice for a longer tear (final: ~600ms animation, navigation at ~500ms).

**Why:** the first web boarding-pass tear moved only the stub's contents over the ticket's own identical background, so the user saw stamp art sliding across an intact ticket and reported "tear off doesn't look right, it should tear imperfectly at the dotted line and be slightly longer." The approved fix added the stock + underlay + jagged clip edge and lengthened the sequence (nav delay 180ms to 360ms, overriding the spec's ~250ms cap at the user's request).

**How to apply:** any future tear/peel effect (e.g. the mobile boarding pass): check where the surface's background is actually painted before animating a child away, and expect "clean + fast" to read as nothing happening. Web reference implementation: gujarati-coach home pass (`animate-stub-tear` in index.css, tear vars in the :root tuning block).

## Finishing the tear across a route swap (hand-off overlay + gust)

**Rule:** when a tear (or any exit animation) must outlive the page's unmount, hand off at the NAVIGATION beat, not at activation: in the same timer callback that calls `navigate()`, clone the mid-animation pieces into a `position:fixed` container on `document.body` (never a React portal — it unmounts with the page) and resume their keyframes via inline `animation-delay: calc(-1 * <nav-delay var>)` (inline delay outranks the class shorthand's implicit 0s). Spawning at activation instead forces double-paint/visibility juggling and inherits the press-scale's shrunken rects; spawning at nav gets a settled layout and a pixel-perfect swap in the same frame React unmounts the originals.

**Traps:** (1) place clones by layout offsets (`offsetParent` rect + `offsetLeft/Top/Width/Height`), not `getBoundingClientRect` of a transformed element, and pause any ancestor breathe/scale while tearing; (2) a container-level `animationend` listener hears the clones' own keyframe ends bubbling — filter by `animationName` (and a marker attr on the last-ending wrapper) or the overlay dies early; (3) always pair with an idempotent timeout fallback (backgrounded tabs/jsdom never fire animation events) read from a :root var BEFORE any DOM write so a failing style read can't orphan a node; (4) jsdom tests: every test that lets the tear reach navigation leaks a real-timer overlay whose clones duplicate page text — purge `[data-tear-overlay]` in a file-level afterEach or later `getByText` calls find multiple matches.

**Gust exit:** pieces that survive the swap need somewhere to go — wrap each clone in a staggered transform/opacity "gust-away" wrapper drifting each piece along ± its own tear trajectory (per-half inline `--gust-x`/`--gust-r` referencing :root constants), never a morph toward the destination page's header element. Web reference: gujarati-coach home.tsx `spawnTearHandoffOverlay` + `gust-away` in index.css.

## Mobile (RN) translation of the same recipe
RN has no clip-path or drop-shadow filters, so the mobile pass card port does it differently while keeping the read: each half is its own View carrying the card bg + rounded OUTER corners, the rip edge is a static jagged rn-svg zigzag strip (`TornEdge`) butted against the half's inner edge, and the parent card goes fully transparent (bg/border/shadow/overflow all off) for the tear so the page shows through the gap. Halves animate transform-only via reanimated. Navigation is a plain `setTimeout(onPress, 500)` inside a ~600ms tear with reset at 1200ms — re-presses during the tear are swallowed by a ref flag, timers cleared on unmount, and reduced motion fires `onPress` immediately with no tear. Android caveats (device-verify): shadows/elevation are invisible on transparent parents, so the tear halves need their own `elevation`, and glow-style shadows may simply not show.
